拍時間發生什麼音效
①拿起0–180ms上浮 6px、放大 1.028、微傾 −0.9°（手拿著不會完全平），陰影同時變深變散（離桌面遠了）紙被拿起 · 窸窣
②端詳180–426ms停住不動。這 246ms 的停頓才是儀式感的來源——少了它就只是一個縮小動畫—（停頓要真的安靜）
③放下426–820ms退到 0.968、透明度 .34、陰影收緊變淺（貼回桌面）、旋轉回正紙落桌面 · −3dB

scale 與陰影必須同時變。只做 scale 會像「放大」，只做陰影會像「浮著但沒動」。--sh-rest → --sh-hand → --sh-back 三段是這個動畫的骨架。

兩個必須守住的節制

①動畫不擋操作。三張紙連著填就是 2.5 秒的動畫。下一張紙在第③拍一開始（426ms）就亮起來，不等動畫結束；使用者中途點別張紙，動畫立刻被打斷。跟「快取不該有權力拖垮主流程」同一條——動畫是說明手段，不是收費站。

②手動離開只播「放下」（短版 320ms）。單選自動推進是系統主動交棒，需要三拍來說明；但使用者自己點了紙二，注意力已經走了——這時紙一還在眼前表演「拿起來端詳」是搶戲。

複選的紙不自動推進（「和誰同行」可以圈三個，系統無從知道他圈完了），所以紙一永遠走短版；紙二、紙三是單選，走完整三拍。

⚠️ 實作注意

box-shadow 不要放進 keyframes——它不上 GPU，三張紙同時動會掉幀。改成一個 ::after 陰影層，動畫只動它的 opacity。prefers-reduced-motion 時三拍全部取消，直接切狀態。

五個優化 · 落地情形

#做法
①紙一分兩區：上區「幾個人」單選（自己一個人／兩個人／一群人）、下區「還有誰一起」複選，中間一條虛線。
選了「自己一個人」→ 整個下區退場（淡到 .26 ＋ 一行手寫「一個人的話，這一區就跳過了」），而不是逐項擦除。不適用的是一個「區」，一句話就解釋完了。
②步調紙放大一階：選項內距 +2px、副標 10→10.5px、間距 10→13px。差異小到說不出來，但排序感受得到。
③摺邊寫「還有 4 種」＋第一次進頁時摺頁自己翻起 12° 再收回（ktPeek，延遲 900ms、歷時 1.1s）。內容改成 寵物／推車或輪椅／同事／同學——「推車或輪椅」直接影響無障礙需求，比「三代同堂」有用得多，而且它是行為描述不是身分標籤。
④預算三級各帶推估區間（用重層已有的目的地＋幣別）。手寫斜體、墨色較淡——它是後來補上的旁註，不是印刷的正文。
⑤票券鈕上那行字可點：「沒圈選，使用標準的節奏安排」→ 點一下就在「標準」上畫一個虛線圈並捲過去。虛線＝我幫你決定的，不是你決定的。使用者看見了一個動作，不安就消失了。

✨加分③ · 矛盾用旁註，不用對話框

圈了長輩／推車輪椅 ＋ 緊湊 → 不彈警告，而是在「緊湊」那個選項底下浮出一行手寫小字。旁註要旁得到東西才叫旁註，貼在紙的角落就只是一句評論。

兩個實作要點：絕對定位、不佔版面高度（它出現時不能把下面的東西推走——這頁的紙已經夠滿了）；提醒但不擋——使用者堅持要緊湊就讓他緊湊，這是入口頁那套三態的同一個原則。

目前觸發的組合：長輩／推車輪椅 ＋ 緊湊、長輩 ＋ 省著花、帶孩子 ＋ 緊湊。

💰 預算這張紙的三條規矩（2026-08-09 定案）

#規矩為什麼
1不含機票與住宿。只涵蓋吃、玩、車資。機票住宿是離散的大額決策，波動極大（飯店淡旺季差三倍、機票差五倍），而且使用者通常已經訂好。拿掉它們，這個數字才從「不可能估準」變成「可以估個大概」。
⚠️ 副標裡不能再出現住宿等級（原本的「商務旅館」「青旅」已移除），否則範圍自相矛盾。
2金額永遠不進 prompt。進 prompt 的是 lean/mid/rich 這個等級。不是因為數字不準，是因為它是冗餘的——「好好吃一餐、累了就搭車」這個行為描述已經完整表達了約束。同一個約束給兩次、形式還不同，只會製造衝突；更糟的是 LLM 可能開始湊數（為了湊到 ¥12,000 硬塞一個景點），那是數字驅動的行程，不是體驗驅動的。
例外：使用者自己輸入的金額該進 prompt——那是真實約束，不是猜測。（未來）
3選項描述行為，不描述等級。「奢華」每個人的定義不同（希爾頓 vs 一晚 4500）；「想訂的餐廳就訂、想搭就搭」是一個具體的決策規則——LLM 照著做得出來，使用者也知道自己選了什麼。這是這一頁「行為語言 > 身分標籤」在預算上的同一個應用。

⚠️ 留給 ⑨ 的問題

「機加酒使用者自己訂完再匯入」意味著生成當下不知道他住哪，而住宿位置決定每天的動線起點——行程只能給到地區級。匯入住宿必須觸發重排；如果匯入只是把文件存成附件，那「不含機加酒」就從一個聰明的簡化，變成把不準確往後推的決定。

資料面：DestinationDeep 新增 budget

budget?: {
  lean: string;   // 「約 ¥4,000–8,000」
  mid:  string;
  rich: string;   // 「¥20,000 起」
};              // 一律**不含機票住宿**、幣別跟隨 intel.currency

加在現有的重層呼叫裡（不是第三顆呼叫）——重層在 step1 驗證通過那一刻就開始背景跑，使用者填 step2–5 時早就回來了。零額外呼叫、零額外快取表，只是輸出多約 60 token。

prompt 要明講三件事：①排除機票與住宿；②區間開寬（窄區間是假的精確度）；③措辭保留「約」「起」。

快取：kt_dest_deep_v3 → v4；伺服器端 deep: 舊資料由 Kelvin 清空重生（目前僅 3 筆，成本可忽略）。前端仍要對缺 budget 退位（不顯示錨點那一行）——「呼叫端一律要有退位」。
