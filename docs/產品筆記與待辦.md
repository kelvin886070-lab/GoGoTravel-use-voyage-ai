## 0. 北極星與判準
- **目標**：批敵市場上的成功商品（競品級，不是「驗證體驗」級）。
- **深度判準**：每個功能問一句「**這是不是有了資料才解鎖的獨門把關/價值？**」——若只是換皮或打勾，就是流於表面。
- **兩條護城河**：閉環（匯入 → 把關 → 一站式導購 → 分潤）＋ 資料飛輪（匯入的資料回頭餵行程、餵提醒）。

## 1. 已鎖定的設計原則（勿違反）
1. **簽名語言**：票券 × 編輯雜誌。色票 INK #232320 / PAPER #F6F1E7 / 深綠 #3F6B52 / STAMP紅 #A23B2E / MUTE #8A8266 / BORDER #E0D8C6；serif(站名) / mono(代碼時間) / sans(內文)。
2. **承諾＝交付**：文案講的，系統一定要做到（照顧模式尤其）。話術不准跑在功能前面。
3. **單一真相＋視圖不副本**：bookings / travelers 是 user 層級真相，行程頁只是視圖（查出來的）。唯一例外：`trips.origin / start_date / end_date` ＝ 單向投影快取（只能 booking→trip 寫，使用者不直接改）。
4. **照顧標籤 ≠ 身分關係**：大人／嬰兒／小朋友／長輩＝觸發「提醒」的旗標，不是稱謂（阿姨/叔叔）。預設大人、只標例外。
5. **溫暖 vs 事實**：情感時刻（親子/孝親確認、loading）可溫暖有品牌感；系統狀態文字要冷靜講事實、不喊口號、不用「！」。
6. **PII / 安全**：護照/生日等敏感個資 → 獨立欄、永不進 LLM、feature flag，統一留給未來「安全與合規」任務（見 B 區）。
7. **匯入方法**：PDF 走前端 pdfjs 抽字（隔離在 `pdfText.ts`，未來原生只換這顆）→ 文字給 LLM；只送文字不送整檔（省 token、避 payload 上限）；掃描檔 fallback 待做。
8. **三層對帳 ＋ precedence 拆兩維**：`Activity` 有 `source` 血統（booking / generated / user）。衝突時**「時間／存在」由事實(booking)決定、「內容／選擇」永遠歸使用者**——機票說上午沒了，是把使用者的活動「往後搬」，不是刪。**對帳器只搬、只標，永不刪 `user` 活動**；當天塞不下 → 退「待安排」托盤（看得見撿得回），絕不蒸發。LLM 重生成只填 `generated` 空洞，碰都不准碰 `user`。
9. **免費 vs 付費界線（界線＝斷層線）**：決定性對帳（硬錨投影／衝突偵測／骨牌重排／待安排／拖拉）**永遠免費無限**——用完額度的人行程也絕不會是壞的。只有「**LLM 把整趟重排到最順**」計付費額度（初次生成＋每次 AI 重排＝1 次）。**此付費/額度機制 solo 自用階段不實作，上架前再議**（見 B 區 B8）。
10. **活動掛相對天數、絕對日期是投影**：`Activity` 掛在 `TripDay.day`（第 N 天）下，`TripDay.date` 只是 trip 層級的絕對日期投影。→ 改日期（如沖繩 11 月→1 月）純位移（天數不變）時，行程結構與已排活動**全部存活**；只有「綁絕對日期的錨」需重新對帳：① 舊訂位跟新日期對不上 → 對帳器揪出；② 季節敏感內容（賞楓）→ 提議（不強迫）重排。收掉舊懸案「投影 vs 手動日期」：手動改日期後再匯入同月訂位自然對齊。
11. **TripConstraints 常駐可編（表單換骨）**：表單不再把輸入壓成 prose 生成一次即丟，而是填**結構化、存在 trip 上、可再讀可再編**的 `TripConstraints`；生成／把關／對帳全部改讀它。拼 prompt 的工作**下沉到生成層**由結構化約束現拼（一進 prose 就資訊死亡）。**硬約束**（booking／確切航班，hard-confirmed）與**軟偏好**（步調／興趣，hint）**分槽**；hard-confirmed 存在時 UI **完全無視** hint（hint 只是沒 booking 時的備胎）。生成的硬門檻只有「**目的地**」；日期／其餘全可後補。
12. **buffer 用算的、pace 是佈局目標**：buffer＝相鄰活動的間隙（`下一個開始 −（這個開始＋時長）`），**純函式現算、絕不存**（存了就是第二真相、會飄移）。pace 是對帳器佈局時瞄準的 slack 目標（悠閒→大間隙／特種兵→小間隙但明示容錯低），**不是**存進每個間隙的欄位。「待安排」托盤是 day/trip 上的獨立清單，**不進 `Activity`**。
13. 🔴 **推薦與生成永不互通（反腐化，2026-08-09 定案）**：**行程生成不知道有哪些飯店／商家合作**——生成層的輸入裡不存在合作名單、佣金率或任何商業訊號；導購只在**行程定案之後**作為獨立步驟發生，排序依據永遠是「離當天行程多近」而非佣金高低。這是推薦系統的經典腐化路徑，而且**它會自己發生**（不需要有人做壞事，只要有人把轉換率當優化目標）。任何違反的優化提案都必須在 `行程頁生命週期設計.md` §8-G 留下記錄與理由——**不是禁止改變，是禁止悄悄改變**。現在寫的成本是零；有營收再寫，就是在跟自己的收入談判。
14. **金額是輸出，不是輸入（2026-08-09 定案）**：使用者選的是**行為傾向**（「想訂的餐廳就訂」），不是金額；LLM 依此挑選項目，價格是**選擇的後果**。我們**自己估的金額永遠不進 prompt**——不是因為不準，是因為它**冗餘**：行為描述已完整表達約束，同一個約束給兩次還形式不同只會製造衝突，更糟的是 LLM 會**湊數**（為了湊到 ¥12,000 硬塞一個景點）。例外：**使用者親手輸入的金額**該進 prompt——那是真實約束不是猜測。
15. **偏好學習：沒有訊號 ≠ 滿意（2026-08-09 定案）**：使用者從沒按過「太貴了」，只代表**我們不知道**，不代表他滿意——**不得把沉默當成認可**去強化任何偏好。承接「學行為，不學內容」：只有**明確的動作**（刪除、替換、按下「換便宜一點的」）才算訊號。
16. **時間一律開頭、去工程味文案**：行程列表與變更說明**時間都放最前**（`14:30　首里城`），整齊有條理。系統文案全走**安心陳述**：不用箭頭 `→`、不用「釘死/已鎖定」這類技術詞（改「這個時間已為你固定」）、不俏皮、不喊口號、不用「！」。承接前面第 5、9 條。

## 2. 資料模型（現況）
- **bookings 表**（獨立、RLS 綁 user）：`kind(flight|hotel)`、`pnr/flight_no/dep_at` 反正規化＋索引（跨行程時間軸、變更反查）、`segments/passengers/hotel/fare` jsonb、`trip_id`（nullable）、`file_url`、`source`。
- **travelers 表**（user 層級、跨行程重用）：`legal_name / nickname / pax_type(adult|infant|child|senior) / aliases / is_self`。
- **鐵律**：`trip_id` 放 booking 上且可 null（訂位優先流／變更反查）；刪行程時 booking 不刪、`trip_id=null`（歷史保留）；travelers 靠 legal_name/aliases 自動配對、跨行程重用。
- **變更通知反查鍵**：`(airline, pnr)` 或 `(flight_no, dep_date, passenger_name)`。

### A′. 訂位匯入的使用者行為邊界（本輪深挖，穿插進上面）
- **[急] 刪除/移除訂位**：匯錯信、訂位被取消 → 目前無法移除，會卡在行程。B 區補刪除入口。
- **[把關·便宜] 房間/人數合理性**：如「1 間 9 人？」「機票 9 人 vs 訂房 guests 不符」→ 純數字比對、不誤報，塞進「行程把關」。
- **[偵測] 取消**：航空/飯店取消信 → 偵測 cancelled → 標記/移除（未來）。
- **[投影衝突] 投影 vs 手動日期**：匯機票會覆蓋 trip 日期，可能清掉使用者故意留的 buffer 天。→ 只在 trip 無日期時投影，或提示「用機票日期覆蓋嗎」。
- **改期**：同 PNR 時間變 → 去重鍵 pnr 優先，重匯正確更新 ✓（已驗）。去重鍵**不含日期**（改日期＝更新不新增，已修）。

### E1. ★★★ 設計憲章・紙與筆（2026-08-02 定案，適用全 App 非僅表單）
1. **「紙＝可書寫處」**：畫面出現紙，只因為那裡要下筆。標題／說明／背景維持 ink-on-photo（無容器）；**凡需圈選、勾選、寫字的區域才鋪紙**——使用者看到紙就知道可以動手，零學習成本。月曆／日曆同屬可書寫處。
2. **紙上用墨、照片上用金**：同一支筆，載體決定墨色——紙上 `#232320`（真筆記）、暗照片上燙金 `#C9B98F`（唯一在暗底站得住的貴氣色）。
3. **統一色、分化質（紙家族）**：品牌紙色**唯一** `#F6F1E7`（護照色，全站不改）；差異全由表面處理製造——①**證件紙**（護照內頁/資料頁）：平整、極淡防偽底紋、切邊、無斑；②**書寫紙**（表單圈選區、月曆日曆）：揉紋摺光（SVG feTurbulence＋feDiffuseLighting，強度約參考圖四成）、邊緣氧化暖褐、**毛邊只給「單張紙」物件**（月曆/日曆——全部毛邊會偏手作剪貼簿，失學院嚴謹）、可下筆；③**票券卡紙**（票根/登機證/行程卡）：挺、齒孔、無揉紋。看起來偏暖＝疊了氧化層，**基色一個位元都不動**。→「同一種紙，不同的使用痕跡」＝比色票統一更高明的一致性，且直接是未來周邊的產品線分類。
4. **選擇的語言＝筆**：點選＝手繪墨圈（SVG 描邊動畫 ~0.42s＋筆觸音效，**筆跡帶 seed 抖動永不重複**）；**取消＝橡皮擦**（再點一下即擦，不做模式切換；擦頭 260ms 掃過、墨跡先淡成 12% 殘影再消失＋紙面摩擦聲——留痕＝物理誠實）。單選情境換選＝先擦舊圈、再畫新圈（改變主意的完整敘事）。**膠囊/實心色塊選項全面退役。**
5. 效能規格：紙紋濾鏡**離屏一次生成、全 App 共用同一張紋理**（等同貼圖但零圖片資產）；真機驗收時量測。素材授權：**一律自產或有授權**，圖庫浮水印素材永不進 repo。
6. **行為語言，不是身分標籤（2026-08-09 定案，全 App 文案原則）**：描述**我做了什麼**，不要評價**使用者是誰**。<br>❌「已開啟長輩友善模式」／✅「行李單多了藥盒和健保卡」。<br>❌ 預算選項叫「奢華」（每個人的定義不同）／✅「想訂的餐廳就訂、想搭就搭」（一個具體的決策規則——LLM 照著做得出來，使用者也知道自己選了什麼）。<br>⚠️ 身分標籤還有一個現實風險：使用者跟父母一起看螢幕時，**被貼標籤的人就在旁邊**。
7. **會消失的東西不能承載重要的事（2026-08-09 定案）**：toast 適合「你剛做的動作成功了」（使用者正看著、事情已完成）；**不適合「我幫你做了一件你沒看到的事」**——那件事的結果在別的地方，而 toast 三秒後就沒了。<br>正解是**把告知放在結果本身上**：自動加進提醒清單的項目帶一行手寫旁註「因為有長輩同行」——不會消失、可追溯、可整組撤銷，而且使用者是在**他自己滑到那裡、正要看的時候**讀到。<br>判準：「如果那個 toast 沒被看到會怎樣？」答「沒關係，之後會看到」＝它本來就不需要存在；答「那就糟了」＝它不該是 toast。<br>而**最好的時機通常在事情發生**之前**（⑧確認與生成幕），不是之後——那時他還來得及改。**
8. **動畫是說明手段，不是收費站（2026-08-09 定案）**：任何轉場都**不得阻擋下一個操作**。下一個目標要在動畫的最後一段**一開始**就可用（不等播完）；使用者中途做別的事，動畫立刻被打斷。與「快取不該有權力拖垮主流程」同源。<br>另兩條配套：**①停頓是敘事的一部分**——「拿起→端詳→放下」的中間那一拍必須真的停住（連續 ease 會變成單純的縮小動畫，儀式感來自停頓）；**②系統主動 vs 使用者主動要用不同長度**——系統自動交棒需要完整動畫來說明；使用者自己點走時他的注意力已經離開，這時還在原地表演就是搶戲（用短版）。

## 5. 深層思考備忘（避免流於表面）
- **「幾天幾夜」要升格成一等公民**：行程目前只有天數，沒有「需幾晚」的概念（`nights = days - 1`，但受抵達/離開時間影響，例如深夜到、清晨走）。沒有它就算不出住宿覆蓋、也做不了 A1/A2 的交叉驗證。→ **先把「行程需幾晚」模型補上，A1/A2 才站得住。**

## 6. 行程頁地基審查（商品化，Foundation F1–F4）
> 目標：從「作品級」升到「商品級」（單一真相＋穩定身分＋可預期變更），為上架灌漿。此為資料模型/邏輯層，視覺獨立後做。

**核心診斷**：行程頁有(1)兩套互相打架的時間引擎、(2)活動沒穩定身分、(3)一顆帶副作用的「重算時間」函式——三者是所有反覆 bug 的共同根。

**四條裂縫（舉證）**
- `recalculateTimeline`（`timeline.ts`）**覆蓋時間**：只留第 0 張卡時間，其餘用累加 duration 重算 → `handleUpdateActivity` 存完馬上被它蓋掉＝**「編輯時間存不進去」真兇**。
- 同函式**偷插卡（副作用）**：`ensureArrivalProcess`（首張 flight→自動插「入境審查」）＋`ensureGapConnectors`（兩定點間插「移動 15min」）→ **抵達 preamble 其實是它每次自動插的，非 LLM**；插的卡**無 id**。
- **無穩定 `id`**：生成/自動插卡都沒 id；編輯/刪除靠陣列索引 `{dayIdx,actIdx}`（`handleUpdateActivity/Delete`）→ 索引位移就編輯到錯卡。
- **兩套時間引擎**：舊 `recalculateTimeline`（線性累加/覆蓋/自動插/跨午夜 `%24h`→存 `00:50`）vs 新 `reconcile`（錨/骨牌/buffer/優先級/溢位/跨午夜 `>=1440`）跑在同一份 days → 新增走舊、匯入走新，結果不一致（購物排在入境前、重複地點、月亮不亮 全是這打架的產物）。

## 9. 產品靈魂 · 底層邏輯（策略思辨定稿，勿遺漏——這決定每個功能怎麼設計）

**A. 使用者在乎什麼——不是一個真相，是幾條軸 ＋ 五股深層力量**
- 五股普世力量（JTBD）：**安心**(不出錯/後悔)｜**我的**(客製、非罐頭)｜**不累**(規劃與旅途都別累)｜**值得**(錢/時間/力氣划算)｜**回味**(能炫耀/記得)。
- Trade-off 軸（像 Uber Eats 的排序，讓使用者調自己的優先）：打卡必去↔在地私房｜緊湊↔悠閒｜省錢↔奢華｜出片↔深度｜**帶誰**(決定最多)。
- **鐵律**：「出片率」只是「回味」的一個面，**不是普世真相**。現在把出片指令焊死＝強迫所有人用同一種排序（像 Uber Eats 逼你用「最快抵達」）。→ 讓使用者調，別焊死。

**B. 從「問」到「學」——但旅遊資料稀疏，兩者互補**
- 旅遊 vs 外送：低頻/高風險/回饋慢 → 行為飛輪天生弱、資料稀疏。
- **問＝冷啟動**（高訊號×只有他知道×來不及學×錯了代價大：目的地、帶誰、硬限制）。**學＝暖機後越來越懂**。
- **主戰場是「單趟的草稿→反應迴圈」**（一趟之內每個留/砍/加/調都是訊號，稀疏不是問題）；跨趟口味是慢紅利。
- **學的機制（可落地、非重 ML）**：活動→小特徵向量（類型/類別/價位/出片度/在地度/耗體力）；動作＝訊號且權重不同（**加/釘/調＝強**、留＝弱、**砍＝模糊訊號權重低**）；累積成**偏好檔案**。三個坑：①歸因雜訊（砍可能是太累/太遠→模糊時用一句便宜問句確認「學＋確認」）②**黑箱＝不信任**（檔案要看得見、可修正）③**綁情境**（孝親vs情侶偏好不同）。

**C. 認出 > 想出（recognition over recall，全站原則）**
- 決策規則：**預設給「認出」（幾個可反應選項）＋ 永遠留「想出」逃生口（搜尋）**。空間小可策劃→chip；空間大/開放/私人→搜尋。
- 模式：**提議(認出)→反應→搜尋(想出)**（＝多城市卡「重點 chip＋其他搜尋」）。
- 治理防失控：做成**一顆共用元件**全站重用；攤出的選項**用學到的偏好排序**（認出 UI × 學到的排序）。

**D. 社交 = 資料引擎（真正的 moat）**
- 社交不是貼上去的功能，是**唯一能讓稀疏旅遊資料達到 IG 級推薦的來源**——機制＝**協同過濾**（從「像你的一群旅人」學，補個人稀疏資料）。
- **護城河＝資料 × 網路效應，不是演算法**（演算法可抄；獨有的真實行程資料＋飛輪不可抄）。
- 差異化：**「真實的、像你的人、真的走過的行程」（可 fork）** 完勝 IG「網紅精修 highlight」（實用 vs 虛榮）。
- **分期（冷啟動）**：現在＝單人學習＋安全網（N=1 就有值）＋**資料模型設計成「社交就緒」（可分享/fork、反應以可協同過濾格式存）**；社交推薦引擎留到有規模。**先種種子、別急著長樹。**

**E'. 鐵律 · 低摩擦捕捉 → 延後的甜美回報 ＋ 隱喻隨生命週期演化**
- **產品鐵律**：純記錄有負擔、人會懶 → 給誘因、讓他**順手就記完**，資料自然累積 → 之後產出甜美 payoff。用在照片、記帳、學口味（＝同一條飛輪，等於 B「從行為學會」）。
- **隱喻隨生命週期演化**：規劃臉＝**A 登機證存摺**（勾期待）→ 旅途**無負擔捕捉照片**（時間＋定位自動貼到當下活動，一鍵；且是社交/護城河的真實資料）→ 回憶臉＝**B 旅遊誌**（照片長出雜誌、拉起回憶）→ **C 手帳式文字回顧**（回憶臉選配）。
- **封面也演化**：規劃＝目的地嚮往照（Google Places 自動抓、可上傳替換）；回憶＝使用者自己拍的最佳一張。
- 捕捉照片：opt-in、**app 建議、使用者確認**（「你在南禪寺拍了 5 張，加進行程嗎？」），不偷抓，守隱私與信任。

**E. 目標函數 · 健康 vs 有毒的參與**
- 追求 IG 級**相關性**、拒絕 IG 式**成癮**。成功指標＝**「規劃得好、安心出發」**，不是停留時間。
- 紅線檢查：**「他離開時有沒有變得更好？」** 每次打開更有準備/更期待/多收好點子＝健康；覺得浪費/焦慮/被操弄＝毒。
- **參與度＝副產品/健康訊號，永不當目標去 hack**（一旦「為拉開啟率而做功能」就是掉毒第一步）。
- 每日「想打開」靠**價值×情感**跨生命週期賺（規劃多次進出、準備期待倒數、旅途天天用、回味）；**空窗期靠發現/社交/時機情報**（＝社交把週期性工具變日常習慣）。

## 10. 規劃臉簽名系統 ＋ 心願盒/錢包 IA（視覺階段 · 紅隊定調）

**簽名視覺（規劃臉，已 mockup 定稿方向）**
- 封面：目的地嚮往照（Google Places 自動抓、可上傳替換）；**乾淨、不放功能鍵**；右上只留 分享/設定（純白圖示＋柔陰影，**放棄玻璃感**——玻璃與「票券×letterpress 紙感」簽名衝突、可讀性隨背景變動）。
- **封面功能鈕清理（落地）＋ interim 防斷入口**：移除封面 [憑證][心願盒][行前提醒][錢包] 那排、回歸乾淨。**憑證**已有家（保管箱分頁）可直接移。但**心願盒(暫存)/錢包/提醒**新家未建（心願盒→靈感頁/＋新增、錢包→行前準備、提醒→行前準備/情境）→ **不可直接刪以免斷入口**。**interim＝暫收進 設定(⚙️) sheet 的「此趟」區**，封面外觀維持只剩 分享/設定；待各自新家建好再遷正。
- 卡片：**時間在前**（紅 mono）、地點襯線、縮圖在左（呼吸感）。角色差異化保留（記帳拍立得微傾角）。
- **連接卡＝A 帶標籤瘦條**（WALK/SUBWAY mono；決定：A 的空間呼吸感 > B/C 的緊湊，避免景點排擠）。緩解密集日：**<5 分鐘步行自動收合成細線**（待辦）。
- 當日抬頭：**保留「大襯線日期」樣式；標題＝城市（京都），移除詩式「風格」膠囊**（它一直做雙職務、兩頭空）。日抬頭純剩城市＋日期（三版式待選）。
- **穿搭靈感＝獨立功能，移到準備臉／前夕**（不再擠日抬頭）：每天一套、**看天氣＋當天行程**給實用建議（如「京都 18°C 微雨、寺廟石階多→好走的鞋＋薄外套」），非一句詩＝真正放大當初「穿搭靈感」的價值、且是差異化。屬準備/前夕階段設計。
- **深墨票根（左右打孔）樣式 → 改用於機票卡**：匯入機票時，**入境一張、出境一張深墨 boarding-pass**，頭尾收束整趟（接「訂位投影：機票＝頭尾邊界卡」）。打孔票券感天生＝機票。
- 列表/地圖：輕量小 toggle、**跟內容捲、不釘死**；**匯入訂位折進「＋新增」**（取消常駐紅虛線鈕）。

**心願盒 → 全域（決定）**
- 使用者故事：日常/旅途看到 IG 推薦 → **一鍵存** → 旅途打開 app → 依**定位＋類別**（小吃/咖啡/市集…）濾出「離我最近」→ 挑有興趣的加入、直接過去。
- 架構鐵律：①**trip 不擁有、是查詢**它——用當前定位＋既有 haversine 依距離/類別濾「附近的」；加入某天＝wish 升級成 activity。②**「一鍵存」必須真的一鍵**——IG 不乾淨吐地點，捕捉當下只存**原始連結/截圖**（瞬間），**地點延後解析**（承 E' 低摩擦捕捉→延後回報）。③資料＝**使用者層級**集合（place/type/source/coords/note），不掛單一 trip。
- 紅利：順手解**新行程冷啟動**（存了 N 個點 → 直接開一趟）。
- 家：放**首頁/全域層**（非規劃臉封面抽屜）；規劃臉內改成**旅途中的情境提示**（就地「你存的 X 就在附近 · 加入？」，比固定抽屜更貼 JTBD）。

**錢包 → 準備臉（決定）**
- 理由：行前已知花費（機票/住宿/門票）＝準備臉匯入的文件，記帳入口跟文件同處。旅途另有錢包（視覺再設計，晚點做）。
- 鐵律：**帳本是「一本」trip 級 ledger，入口分兩處**（準備臉＝已承諾成本、旅途＝臨時捕捉），底層同一本才結算得出。→ **匯入訂位時同步落一筆帳（金額＋付款人＋分帳）＝「匯入即記帳」**（接地基第二輪 ledger 實體）。

**連帶結果**：規劃臉封面下**那條票根工具列作廢**（兩顆都搬走）→ 封面之下**留白、行程直接當主角**（已定，不放 trip 級元素）。

**時刻三 · 心願入規劃臉（決定）**：不塞「盒子」，溶進**既有的兩個入口**。
- **＋新增保持乾淨**：主畫面只一顆「＋新增」；點開 popup sheet 四項＝**景點／交通／匯入文件／從心願盒挑選**（連動心願盒、濾成本趟城市）。**push＝最輕①**：就藏在 sheet 那項「從心願盒挑選 (N)」的計數，只在「想加東西」時出現，不吵。（＝認出＞想出：意圖出現才給選項）
- **地圖圖釘**（旅途/排程都用）：把心願用不同樣式圖釘疊在城市附近，**屏蔽切換＝篩選／全部顯示／全部屏蔽**（防圖釘把地圖弄雜），點釘→加入某天。

**鐵律 · 編輯即自動接路（決定，核心價值）**：使用者永遠不該自己查「A→B 怎麼去」。
- **資料結構**：**別用字面 linked list（存 nextId）**——拖拉重排易斷鏈、兩個真相、要隨機存取。正解＝**「陣列是順序、連接是衍生的邊」**：真站點＝有序陣列；交通卡＝`array[i]→array[i+1]` 算出來的邊（承 F3 `ensureGapConnectors`／連接投影化）。**任何相鄰改變（插/移/刪）→ 只重算受影響的兩條邊**，時間由 reconcile 骨牌下推。
- **geo-aware**：短程同城→walk/subway 自動估；遠程跨城→**城際交通卡（空間第三刀）**或先跳「跑太遠」把關（haversine＋suggestDayNumber 已可判）。
- **工程**：Directions API 只在受影響邊**惰性重算**＋`(fromPlaceId,toPlaceId,mode)` 快取＋不可用退回 haversine；key 走後端 proxy。交通**自動填但可改**（承 E' app 建議、使用者確認），不強迫填、不擅自鎖死。
- 本質＝把 **reconcile＋F3＋第三刀** 收斂成一條規則。
- **C 已落地（估算版，2026-07）**：`routing.ts`（haversine＋運具門檻估算）＋`reconcile/autoRoute.ts`（isAutoConnector/strip/rebuildConnectors 冪等，相容舊簽名不誤刪使用者交通）＋`timeline.recalculateTimeline` 改用 `rebuildConnectorsInList`（所有編輯共用此管線→全站生效）＋transport 時長優先 `durationMin`。16/16 腳本測試＋tsc 綠。**只在有座標的相鄰定點才路由**，缺座標沿用 15 分預設（不失連接、不 regression）。**待辦**：步驟 6 Directions API 精算（drop 後 debounce＋快取＋退回估算，需 key/proxy）；「walls/parking on every edit（reconcileDay 全面接管編輯）」目前仍走 recalculateTimeline 的前向堆疊（尊重明確時間），未全面接 reconcile，屬後續增強。
- **C 後續（決定，待建）**：①**Directions API 精算採折衷**——只補「大眾/跨城」這種估算會差很多的段（走路/計程估算已夠），**快取＋按需/開啟那天才打**，規劃用估算、成本壓到刀口上；key 走後端 proxy（新開 routing edge function）。②**reconcile 接編輯分兩軌**：**手動編輯（拖/加/刪）＝只警示不自動 park**，在塞不下那張卡旁給**一鍵「收進待安排」**（reconcile 偵測模式算出 victim、不動東西、使用者按了才搬）；**系統變動（匯入/改日期）＝自動 park＋票根提示**（沿用現行）。③**連接卡不吃 pace buffer**（它本身就是移動時間，reconcile 勿在其前後重複加 buffer）。對齊「訂位＞使用者＞生成」＝手動操作最該被尊重。
- **進度（2026-07）**：③連接卡不吃 buffer、②`detectDayIssues` 偵測模式、卡旁溢位警示＋一鍵「收進待安排」（`handleParkActivity`，手動 warn-only、系統變動仍自動 park）＝**已落地**（tsc＋腳本測試 3/3、5/5 綠）。剩 **①Directions API 精算**（需後端 routing edge function＋Kelvin 在 Supabase deploy）。

**手動微調（拖曳）整合（決定）＝同一條「編輯即自動接路」，source＝使用者**
- 加/拖/刪/地圖插入全走一套：改陣列序 → 只重算受影響邊（自動接路）→ 時間骨牌（reconcile）→ 撞錨檢查 → 跨城 geoCheck。**拖曳不特殊化**。
- 規則：可拖＝浮動站；**牆抵抗**（機票錨/固定時間訂位/飯店收尾不被擠走，浮動站繞行）。**優先級 訂位＞使用者＞生成**：使用者拖放＝明確意圖、被尊重，只重算周邊交通＋順移其他浮動站；被拖過的站升級 `priority=user`，順路重排/gap-fill 不得偷偷排回。拖曳當下即時回饋（落點＋結果時間＋撞牆/跨城警示）。拖＝強學習訊號（§9-B）。
