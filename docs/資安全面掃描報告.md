## 二、真發現（2 項）

### 🔴 F-1　pdfjs-dist 高危漏洞：惡意 PDF 可執行任意 JS（可被使用者直接觸發）

- **來源**：`npm audit` → `pdfjs-dist` GHSA-hq66-cqwq-w95j「Arbitrary JavaScript execution upon opening a malicious PDF」。
- **為什麼是這批最高**：這**不是理論**。你的訂位匯入 `extractPdfText`（`booking/pdfText.ts`）
  就是用 pdfjs 解析**使用者上傳的 PDF**。攻擊者做一份惡意 PDF、透過「匯入訂位」上傳，
  就可能在瀏覽器端執行任意 JS——而此時頁面裡有使用者的 **Supabase session**。
  即：一份 PDF → 打穿一個使用者的整個帳號（含保管箱存取權）。
- **修法**：`npm audit fix`（升級到 patched 版）。修完務必回歸測一次 PDF 匯入（pdfjs 大版本 API 偶有變動）。
- **縱深**：pdfjs 有 worker 隔離選項；升級後確認 `extractPdfText` 走 worker 而非主執行緒解析。

### 🟠 F-2　`VITE_GOOGLE_MAPS_KEY` 打包進客戶端（金鑰盜用 → 帳單濫用）

- **來源**：`import.meta.env.VITE_GOOGLE_MAPS_KEY` 出現在 5 個前端檔（地圖渲染）。
  **凡 `VITE_` 開頭的變數，Vite 一律打包進 bundle ＝任何開啟 app 的人都拿得到**。
- **這不一定是漏洞——取決於 Google Cloud 那端有沒有上鎖**：
  - 這把是**瀏覽器地圖 JS key**，設計上就會露在前端，**這是正常的**。
  - 真正的問題是：**它在 Google Cloud Console 有沒有設限制？**
    · **HTTP referrer 限制**：只有你的網域（＋ capacitor://localhost）能用這把 key。
    · **API 限制**：只勾 Maps JavaScript API，不要開放全部。
  - 若**未設限**：有人抄走 key，拿去他自己的網站狂打，**帳單算你的**。
    這和 ai-proxy 後面那些 server key 是兩回事——那些永遠拿不到；這把本來就露，只能靠 Google 端上鎖。
- **無法從程式碼驗證**（是 Cloud Console 設定），請自行確認 → 見檔尾。

## 三、無法從 repo 驗證、需你自行確認（DB/Console drift 風險）

1. **正式 DB 的 RLS 政策是否與 repo 一致**——repo 寫對不代表線上跑過（avatars 就是前車之鑑）。
   驗證 SQL：
   ```sql
   select tablename, policyname, cmd, qual from pg_policies
   where schemaname='public' order by tablename, cmd;
   ```
   逐張表確認每個 SELECT/UPDATE/DELETE 的 `qual` 都含 `auth.uid() = user_id`。
2. **Google Maps key 的限制**（F-2）：Google Cloud Console → APIs & Services → Credentials →
   點該 key → Application restrictions 設 **HTTP referrers**（你的網域）＋ API restrictions 只勾 Maps JS。
3. **git 歷史是否曾提交過真金鑰**（金鑰移進 Secrets 之前的舊 commit）：
   ```bash
   git log -p -- .env | grep -iE "AIza|key" | head
   ```
   若歷史裡有真的 Gemini/Weather key，**該金鑰視為已洩漏**，去對應平台 rotate（重新產生）。

## 四、可自行執行的動態測試（DAST，受控環境）

> 目的：驗證這兩天的補強在**真實流量**下成立。以下用你自己的帳號 token，不對他人資料操作。

**D-1　未登記 action 預設拒絕**（應回 400「未知的 action」）
```bash
curl -s -X POST "$SUPABASE_URL/functions/v1/ai-proxy" \
  -H "Authorization: Bearer $YOUR_JWT" -H "Content-Type: application/json" \
  -d '{"action":"totally-fake-action","payload":{}}'
```

**D-2　gemini-text 不再接受 client 指定模型**（應忽略 model/maxOutputTokens，用伺服端固定值）
```bash
curl -s -X POST "$SUPABASE_URL/functions/v1/ai-proxy" \
  -H "Authorization: Bearer $YOUR_JWT" -H "Content-Type: application/json" \
  -d '{"action":"gemini-text","payload":{"prompt":"hi","model":"gemini-3-pro","maxOutputTokens":65536}}'
```

**D-3　SSRF 白名單**（非 Google 網域應直接回 `coords:null`，不對該位址發請求）
```bash
curl -s -X POST "$SUPABASE_URL/functions/v1/ai-proxy" \
  -H "Authorization: Bearer $YOUR_JWT" -H "Content-Type: application/json" \
  -d '{"action":"resolve-maps-url","payload":{"url":"http://169.254.169.254/latest/meta-data/"}}'
```

**D-4　未帶 JWT 應 401**
```bash
curl -s -X POST "$SUPABASE_URL/functions/v1/ai-proxy" \
  -H "Content-Type: application/json" -d '{"action":"gemini-text","payload":{"prompt":"hi"}}'
```
