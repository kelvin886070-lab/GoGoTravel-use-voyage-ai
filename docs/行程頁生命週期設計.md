## 0. 願景與護城河

**情緒北極星**：讓使用者用了突然覺得——「原來旅行可以**無腦玩**，玩完**不擔心分帳**，還有**回憶可以記錄**」。

**兩層護城河（疊起來才是真護城河）**
1. **閉環**：涵蓋一趟旅程的**完整生命週期**，且每段餵養下一段。單一功能會被抄，閉環與資料累積抄不走。
2. **資料飛輪**：旅後資料（實際走法、改動、記帳、打卡、最愛）→ 餵養 AI 生成 → 下一趟更貼近使用者 → 越用越好。體驗隨使用次數單調上升。

## 1. 生命週期脊椎（版面邏輯 = 心路歷程）

一趟旅程在使用者心裡的五個階段，行程頁在每段換「主臉」：

| # | 階段 | 行程頁給什麼 | 服務階段 |
|---|---|---|---|
| 1 | 規劃 | 編排行程（列表/地圖） | 排 |
| 2 | 準備 | 補齊機票/住宿/文件、打包、倒數 | 補 |
| 3 | 出發前夕 | 彩排一遍、倒數、最後檢查 | 補/走前 |
| 4 | 旅途中 | 走：下一站/導航/記帳/打卡 | 走 |
| 5 | 回來後 | 回憶/結算/評分 → 餵養生成 | 憶 |

脊椎：**存 → 排 → 補 → 走 → 憶**（靈感/心願盒在上游餵入；回憶迴圈回下一趟）。

**核心分辨**：**「鏡頭」 vs 「階段」**。列表/地圖是**鏡頭**（用什麼視角看同一份計畫）；今天/走是**階段**（你在生命週期哪一段）。舊的「列表｜地圖｜今天/走」三選一是把兩者混排＝概念錯位，這是「不順手 + icon 撞名」的病根。正解：**階段**決定主臉（時間自動＋可覆蓋）；**鏡頭**只是某階段內的內部切換。

### 1.1 情緒主線（emotional arc）＋ 誕生前拍
- **設計原則**：照生命週期**順序**設計，刻意雕琢情緒的**堆疊**，讓整套像有起承轉合的故事（照序過關＝A5 簽名語言逐臉套用＋情緒調校）。
- **情緒音符（一路往上堆到出發峰值 → 沉浸 → 回味 → 再點燃下一趟）**：
  - **誕生（5-step 生成）｜火花** — 「哇，我的行程生出來了」。
  - 規劃｜**期待萌芽**（克制，別太早嗨）· 準備｜**踏實累積** · 前夕｜**興奮峰值**（＋分享） · 旅途｜**沉浸執行** · 回憶｜**回味沉澱** → 餵下一趟。
- **5-step 生成 vs 規劃（釐清、非衝突）**：`首頁 ＋新增行程 → 5-step 清單 → 生成 → 落在「規劃」`。5-step＝**行程誕生（頁面之前的創建精靈）**；脊椎＝**誕生後的生命週期**，故 stepper **不需要「生成」階段**。共用同一引擎/Kelvin 人格：5-step＝**macro 生成**（整趟）、規劃「空白天→Kelvin 幫你排」＝**micro 生成**（補一天）。
- **誕生 reveal（票券母題）**：生成中＝「Kelvin 正在印你的行程票」（Framer Motion 印票動畫）；reveal＝行程**印成一張票**（destination departure board、天數/地點統計、每日精華、READY 戳章、GENERATED BY KELVIN）；「開始規劃」把票折進行程頁。**分寸**：慶祝「為你排好的起點/草稿」非「完美行程」，「重排一版／把它排成你的樣子」設定期待、避免 reveal 過譽。

## 3. 行程頁骨架（chrome）

### A1. 階段/鏡頭控制列 — 已定版
- **脊椎風格**：經典 stepper（icon＋命名）＋ **走過的軌道變綠**。
  - 走過段＝淺綠打勾；當前段＝深綠光暈；未到段＝灰、上鎖。綠軌隨旅程推進。
  - 五段 icon：規劃(list-check) / 準備(luggage) / 前夕(hourglass) / 旅途(walk) / 回憶(photo)。
- **鏡頭是情境出現**：列表/地圖只在「規劃」（走模式自己另有控制）；準備/前夕/回憶是不同內容，沒有列表/地圖可切。
- **selected vs current**：脊椎高亮「你點選在看」的段；「真正的當前段」永遠留一個小「**現在**」標記＋一鍵「**回到現在**」，往回逛不迷路。

### A2. 階段偵測 × 手動覆蓋 — 已定版
- **驅動原則（混合）**：`當前階段 = max(時間階段, 完成度階段)`——誰跑得前用誰。拖延症被**時間**推、有規劃性被**完成度**拉。
- **時間階段（門檻，可調）**：回來後（今天>結束）｜旅途中（今天∈區間）｜前夕（出發前 ≤3 天）｜準備（3–21 天）｜規劃（>21 天或剛建立/沒排日期）。
- **完成度只能拉到「前夕」為止**；旅途/回憶是**硬時間閘**（不可能「準備完」就人在當地）。
- **黏著單調前進、不自動倒退**：刪一筆訂房不退階段，只讓補齊提示重新變吵。倒退只用手動（脊椎點回過去段）。
- **完成度判準**接 B2（見下）。

## 4. 五個階段的主臉

### B1. 規劃臉 — 已定調
- **嚴守保留**：脊椎在上（規劃＝當前深綠）、鏡頭列表/地圖、你熟悉的**卡片語言＋拖曳/加點/vibeTag 全部不動**。規劃臉本質＝你最熟的列表/地圖，不重造。
- **列表/地圖 toggle 置中**（回歸原版俐落）；「已排 X/N 天」進度移到 toggle 下方小字，不搶版面。
- **只新增三塊**：
  1. **規劃完成度可見**：整體「已排 X/N 天」＋（列表中）空白天標示。滿排（N/N）時**morph 成「行程排好了 ✓」ready 態**（不消失＝完成有回饋）、呼應底部交棒 banner。
  2. **空白天的生成邀請**：「Day N 還空著 · 要 **Kelvin 幫你排一版**，還是自己加？」→ 接下游 5-step 生成器。
  3. **規劃 → 準備 柔性交棒**：底部輕提示「行程排得差不多了 → 去補機票住宿」，不硬推。
- **完成判準（統一模型，供 A2）**：**無空白天（每天≥1）＝自動偵測「差不多」→ 浮出交棒 banner（邀請）；使用者點 banner「去補機票住宿」＝明確確認、推進到準備**（等於按了「排好了」）。自動偵測負責浮出、使用者一點負責推進，兩機制協作、零誤判、不藏按鈕。

> **品牌人格「Kelvin」（全站決策）**：App 的助理/生成人格統一叫 **Kelvin**（例：「Kelvin 幫你排一版」），既藏掉「AI」字樣、又建立品牌人格與溫度。全站語音一致，Kelvin＝App 的化身/吉祥物。

### B2. 準備 / 補齊臉 — 已定調（變現核心）
- **工作**：補齊該訂該備、降低「準備好了嗎」焦慮、把缺口變訂單。
- **四核心 × 四態**：機票／住宿／文件／打包；每項＝已備(綠)／缺(琥珀)／不適用(灰)／已自理(標記)。
- **偵測（重要）**：機票/住宿**不掃保管箱**（一人多份文件、會誤報）→ 靠**行程結構**（有 flight 卡／hotel 卡蓋滿每晚）＋使用者**明確標記「已訂/自理」**。文件＝使用者**手動從保管箱挑**（護照/保險）或標記。
- **兩個出口（治狼來了＋變現）**：每缺口 →「**訂**」（聯盟導流＝抽佣）或「**已訂/匯入/標記**」（餵保管箱、關提示）。永遠留輕量「已自理」，不強迫上傳。
- **完成判準（接 A2）**：核心＝**機票＋住宿**，兩者已備/自理即「準備完成」、可提前進前夕；文件/打包**建議但不擋**。
- **優先序**：機票 > 住宿 > 文件 > 打包，只推最前面那個缺的（優先卡）。
- **遊戲化（烘進平常態）**：期待式倒數＋就緒環、完成蓋「搞定」小章、進度框架文案（不是冷「缺住宿」）、里程碑時刻（機票＋住宿補齊 → 脊椎打勾亮進前夕＋一句期待）、分享鉤子。
- **文案原則**：克制＝時尚。平常行乾淨有信心，把「好聽的話」留給里程碑與分享卡。避免硬詩化（「曼谷的夜就定了」被否決）。

### B3. 出發前夕臉 — 已定調
- **情緒**：興奮峰值 + 最後檢查 + 彩排（「萬事俱備，只欠出發」）。
- **Hero 視覺＝票券主題（依交通方式變臉）**：搭飛機→**登機證**、高鐵/火車→**高鐵車票**、其他/沒出發地→**通用出發卡**。三種**共用一個元件、換膚**（吃 `trip.transportMode` 自動選），平面雅緻不浮誇。航段 FROM→TO＋大倒數，撕票根那段放快動作（彩排/最後檢查/分享）。**可疊成收藏**，呼應旅遊護照那條線。
- **內容**：
  1. **大倒數**（在票券 hero 上）＋分享期待卡（前夕＝分享峰值）。
  2. **行前彩排**：接**走 PREVIEW**（用走的視角走一遍、檢查順不順）。
  3. **節奏健檢**：每日總距離/總時 ＋「跳太遠」警示（用相鄰站 haversine；某日總距或單段超門檻＝標琥珀「建議調整順序」）。＝你要的「檢查排得對不對」。
  4. **最後檢查**：臨門項（線上登機/網卡/打包最後一哩）。
- **紅隊**：前夕**別重複準備的訂房催**——機票/住宿此時應已 ✓；checklist 只放臨門項。但若拖延症到前夕**還沒訂**＝**升級紅色急催**。

### B4. 旅途中（走）臉 — 已定調
- **LIVE / PREVIEW 兩子狀態**：LIVE＝旅途中（真實 now、下一站幾分後、GPS 直線距離、導航、勾完成）；PREVIEW＝行前彩排（選日、唯讀、不算真實倒數、不吃 GPS、無記帳）。旅途中自動 LIVE、否則手動 ▶。
- **焦點卡＝捷運三站條**：左＝上一站(dim)、中＝**焦點站大字**、右＝下一站(dim)；連接線帶交通（🚶15 分）＝「如何去」。中間＝「你的焦點站」（前往中＝下一站；進行中＝現在這站）。
- **微循環（選配、非必按）**：前往中 → 我到了（打卡）→ 進行中 → 完成 → 下一站。**時間照樣自動推進**，按鈕是給想掌控/捕捉的人；「我到了」前進時**整條左滑一格**。
  - 前往中動作：導航 / 我到了。進行中動作：打卡 / 記帳 / 下一站。
- **按鈕排版**：**左右一行、主鈕靠右下**（單手拇指區）；省垂直高度。
- **打卡＝拍立得**：拍照＝回憶＋路線貼紙素材。
- **邊界**：今日首站左＝「今日起點」（飯店/機場）；末站右＝「今日尾聲/回飯店」。
- **抵達偵測**：時間自動＋手動「我到了」選配；GPS 自動偵測抵達排原生階段。
- **待收攏**：焦點卡下方完整今日時間軸怎麼擺、FAB(臨時加點) 與進行中「記帳」的分工、打卡→拍立得流程。
- **已建（基礎版）**：TripWalkView（LIVE/PREVIEW）、走↔編輯切換、FAB 記帳/臨時加點——需照上述捷運式重畫。

### B5. 回來後（回憶）臉 — 已定調
- **工作**：回味 → 無痛結算（兌現「不擔心分帳」）→ 沉澱成收藏/資料（飛輪）→ 種下一趟（閉環）。
- **內容優先序**：① 回顧 hero（可分享回顧卡）② 代購結算（**有未結才大聲**）③ 打卡相簿（拍立得牆）④ 收藏/護照（+1 城市＝身分認同）⑤ 輕量「最愛」回饋 ⑥ 再玩/存範本（收頂部選單）。
- **飛輪回饋**：**不做問卷**（殺氣氛）。用行為訊號（打卡了哪些、記帳、停留）＋一鍵「這幾個最愛」，低負擔餵養生成。

## 5. 跨階段引擎 / 資料

- **記帳**：拍立得卡 ＋ 代購結算（SettlementSheet 已建，依 forWhom 跨行程聚合、換算、分享、一鍵結清）。回憶感是賣點。
- **購物/心願**：BuyHere（在這裡要買，綁 stopId，已建）＋ 附近雷達（useNearby）。
- **憑證/文件＝保管箱（已定調）**：組織模型＝**通用證件（跨趟共用）＋各趟文件（trip-scoped）**兩區。
  - **通用證件**：護照/保險/信用卡/駕照——傳一次、每趟都用；因為是**明確單一槽位**，其存在**可直接驅動準備臉「文件」就緒**（護照在＝每趟護照✓）。
  - **各趟文件**：機票/訂房/簽證/票券——依行程分組（當前趟展開、狀態膠囊）。
  - **垃圾桶（刪除行程）分出**、別跟文件混。
  - **就緒和解落腳處**：準備臉「文件→從保管箱挑」挑這裡；「已訂→匯入」存這裡並自動關聯該趟。
  - **註**：機票/住宿仍**不**靠掃保管箱判就緒（文件多、模糊）；只有明確槽位的通用證件才驅動就緒。
  - **視覺＝V2 錢包卡片風**（方向定、細節後調）：證件變彩色卡、各趟文件是票券卡（呼應 B3 登機證收藏主題）。
  - **私密上鎖（opt-in）**：護照/信用卡等可上鎖，開啟要**裝置生物辨識**（別自做 PIN）；完整生物鎖＝**原生能力**，PWA 先做「模糊遮蔽＋開啟前確認」；上鎖證件排除在分享/截圖外、預覽模糊。信任＝「放心」賣點的一環。
- **就緒偵測引擎（跨 A2/B2/B3/保管箱 共用單一來源）**：
  - 四項四態：機票/住宿/文件/打包 × 已備(綠)/缺(琥珀)/不適用(灰)/已自理(標記)。
  - 來源：機票＝行程有 flight/arrival 卡 或 標記；住宿＝hotel 卡蓋滿每晚 或 標記（**皆不掃保管箱**）；文件＝通用證件明確槽位存在＝✓、缺→從保管箱挑或標記；打包＝checklist 完成度（建議不擋）。
  - **不適用態**：無機票的行程（國內火車/自駕團）→ 機票＝灰不適用，不列入完成判準。
  - 兩出口：缺→訂（聯盟變現）／已訂→匯入或標記（餵保管箱、關聯該趟、關提示）。
  - 完成判準（供 A2）：核心＝機票＋住宿（適用時）已備/自理 → 準備完成、可提前進前夕；文件/打包不擋。優先序 機票>住宿>文件>打包。
- **偏好資料 → AI 生成飛輪**：旅後資料回灌生成引擎。
- **通知/提醒**：補齊、倒數、geofence（原生）。

## 6. 分享 / 成長系統

- **全幅故事卡**：A 照片主導 / B 字體編輯，**模板可選**（有美照預設 A、否則 B）。只露目的地＋倒數，角落低調落款 kelvin trip。
- **透明路線貼紙（Strava 式，最強成長引擎）**：白色路線＋統計（天數/地點/國家）＋落款，透明 PNG 壓在使用者**自己的照片**上。路線風格化到城市級、不 pinpoint；字帶陰影任何底圖可讀。
- **各階段版本**：期待/倒數卡（準備/前夕）、旅程回顧卡（回憶）。
- **交付**：完整「貼進 IG story」需原生（IG sticker API）；PWA 先做「生成透明 PNG＋手動貼」。

## 7. 遊戲化原則

- **時尚的遊戲化 = 情緒 × 美感 × 收藏，不是 點數 × 徽章 × 排行榜。**（點數/徽章殺時尚；streak 對低頻旅遊＝製造愧疚。）
- 三支柱：**期待**（離夢想越近）、**成就**（階段前進本身＝獎勵，脊椎打勾亮進下一段＋里程碑時刻）、**收藏物**（旅遊護照/回顧卡＝身分＋可分享）。
- **紅隊底線**：別 trivialize 真實風險（漏訂機票不是過關）；**delight 是配菜、速度與實用是主菜**。

## 8. 商業模式（相關決策）

- **變現**：主動偵測缺口 → 提醒 → **聯盟導流抽佣**（先行、零庫存/牌照/客服）→ 驗證需求後再考慮站內訂（聚合 API）→「直接當旅行社」是後期重資本，不是創業假設。
- **紅隊**：庫存/合約才是護城河非 app 完整度；收錢就擁有所有失敗模式（法規/客服/資本）；Dcard 通路「流量≠意圖≠轉換」，需壓測「他為何跟你合作而非自建」。
- **多人分帳**：輕量**名字制**（像購物 forWhom），先進、不綁死協作。
- **協作**：先不做；但**資料模型別把單人寫死**（owner/payer 保留擴充空間）。
- **匯出 PDF**：新架構版，會與現版差很多，排入。
- **語言/貨幣在地化**：排入。
- **5-step 一鍵生成表單**：行程頁定完後回頭重想（生成器該吐什麼由新結構決定）——後面的任務。

### 8-G. 🔴🔴 反腐化護欄（2026-08-09 定案・現在寫，因為以後就寫不下去了）

**未來的住宿導購**：day1 的行程聚集在哪一區 → 推薦該區住宿。方向沒問題，**但它會產生一個結構性的利益衝突**：如果推薦住宿有抽成，生成行程時就有動機把行程往有合作飯店的區域靠。

⚠️ 這是推薦系統的經典腐化路徑，而且**它會自己發生**——不需要任何人做壞事，只要有人把轉換率當成優化目標。

**鐵律（不可協商）：**
1. **行程生成不知道有哪些飯店合作。** 生成層的輸入裡不存在合作名單、不存在佣金率、不存在任何商業訊號。
2. **推薦只發生在行程定案之後**，作為一個獨立步驟。兩邊資料不互通。
3. **推薦的排序依據永遠是「離當天行程多近」**，不是佣金高低。如果有合作與非合作的飯店距離相當，兩個都要出現。
4. 任何違反上述的優化提案，都要在這份文件留下記錄與理由——**不是禁止改變，是禁止悄悄改變**。

> 現在寫下這條的成本是零。等到有營收再寫，就是在跟自己的收入談判了。

### 8-H. 訂房匯入後的重排（2026-08-09 討論・**留待行程頁詳細設計時定案**）

**背景**：⑥「想怎麼玩」的預算刻意**不含機票住宿**（使用者自己訂完再匯入）。代價是**生成當下不知道他住哪**，而住宿位置決定每天的動線起點——行程只能給到地區級，匯入後需要調整。

**Kelvin 的方案（方向認可）**：不全部重生成（會摧毀使用者已投入的編輯＝不可逆的信任損失），改用**單日重排**，並在飯店離該日行程太遠時詢問。

**紅隊補的三個洞（實作前必須有答案）：**

| # | 洞 | 方向 |
|---|---|---|
| 1 | **系統怎麼知道哪幾天「他安排好了」？** | 每一天要有 `touched` 標記（使用者手動改過）。**沒動過的日子直接重排、只告知；動過的日子一定要問。** 否則七天行程問七次，比不問還煩。 |
| 2 | **只給「排順／重排」少了最有用的那個選項。** | 飯店在北邊、day3 全在南邊時，**怎麼排順都沒用**。真正的解是**跨日交換**（day3 ↔ day5）。因為住宿固定、景點的地理分布也既定——最佳解通常是「重新分配哪一天去哪一區」，而不是「改變去哪裡」。<br>三層選項，干擾由小到大：①**排順**（日內調順序）②**換一天**（整天對調——最有效，而且**不損失任何內容**，使用者自己很難想到）③**重排這一天**（換掉部分景點）。 |
| 3 | **時機：不要在匯入的當下問。** | 使用者剛匯入訂房確認信，心智狀態是「我在整理文件」，不是「我要調整行程」。照憲章**「閱讀與決定是兩個不同的動作」**：匯入時只**安靜標記**（day3 旁浮一個小小的「離飯店有點遠」），等他自己點進 day3、進入「決定」狀態時才給那三個選項。 |

**另外兩個實務問題：**
- **「太遠」的判準該是回程時間，不是直線距離。** 東京 5 公里是 20 分鐘地鐵，鄉下 5 公里可能沒有公車。若不想付路徑 API 的成本，簡化版＝直線距離 × 依 `granularity`（城市／區域）調整的係數。
- **多段住宿**（前三天住 A、後兩天住 B）在長途旅行很常見——飯店不是一個點，是**時間軸上的序列**。重排邏輯要能處理。

### 8-I. 依「主要移動方式」自動生成的準備提醒（2026-08-09 Kelvin 提案・待行程頁實作）

**構想**：⑥「想怎麼玩」問了「主要移動」之後，行程頁的提醒清單可以自動長出對應的準備事項——
自駕 → 國際駕照、租車、保險；大眾運輸 → 交通票券。**用系統的字體讓使用者看得出是系統預設的，
符合需求再加入自己的清單。**（Kelvin 自己推導出了與「⑧ toast」那一輪相同的原則：
告知放在結果本身上、可辨識、可撤銷。）

**三個紅隊點（實作前必須解決）：**

| # | 問題 | 方向 |
|---|---|---|
| 1 | **分區比分字體省力。** | 系統建議放在**獨立區塊**（「你可能還需要」），不要混進他自己的清單再靠字體區分——混在一起，即使字不同，他仍要逐項辨識。 |
| 2 | **「大眾運輸要訂票」是依目的地，不是依交通方式。** | 台灣搭捷運沒有「預訂」這回事；日本可能要 JR Pass；歐洲火車要提前訂。**同一個交通方式在不同國家的準備工作完全不同**——判斷要交給目的地情報，不能只看 `localTransport`。 |
| 3 | 🔴 **合規資訊給錯的代價，和給錯金額不同。** | 金額錯了損失錢；**國際駕照／簽證錯了會租不到車、甚至被拒絕入境**。有些國家不只要國際駕照，還要公證譯本。措辭必須是「你**可能**需要」＋「請向租車公司／使領館確認」，**絕不能寫成斷言**。這條與「金額只給粗估」是同一個家族的規則，但嚴格度更高。 |

**另外**：**按時間釋放，不要一次推六項**——國際駕照在出發前一個月（申請要時間）、租車三週前、交通票券兩週前。一次跳出六項，使用者會全部忽略。
