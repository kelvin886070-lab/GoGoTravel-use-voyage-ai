# 規劃臉視覺定稿清單（準備進程式）

> 本檔＝這一輪「規劃臉」視覺＋互動討論的收斂定稿，供落地時逐條執行。
> 範圍：**只含規劃（行程）臉**。準備臉（行前準備）尚未設計——錢包/文件中樞/匯入分流的另一半落在那，需先設計才能完整落地（見 §6）。
> 內部用「臉」只是隱喻；**UI 一律用使用者看得懂的頁籤名**（如「行前準備」），不出現「臉」。

---

## 1. 簽名系統（tokens）

- 語言：**票券 × 編輯雜誌**。**放棄玻璃感**（與紙感簽名衝突、可讀性隨背景變動）。
- 色：INK `#232320` / PAPER `#F6F1E7` / 深綠 `#3F6B52` / STAMP紅 `#A23B2E` / MUTE `#8A8266` / BORDER `#E0D8C6` / GOLD `#C9B98F`。
- 字：**襯線**＝地名；**mono**＝時間/代碼/數據；**sans**＝內文。
- 顏色語意鐵律：**紅（STAMP紅）保留給訂位/警示**；使用者手動鎖用**墨色**，勿混用。

## 2. 定稿畫面與互動（逐塊）

### 2.1 封面
- Google Places 目的地嚮往照（自動抓、可上傳替換）；乾淨、**不放功能鍵**。
- 右上僅 **分享 / 設定**（純白圖示＋柔陰影，非玻璃）。
- 標題襯線、日期 mono。**封面之下留白、行程直接當主角**（不放 trip 級元素）。
- 票根工具列**作廢**（心願盒→靈感頁全域、錢包→行前準備）。

### 2.2 日導覽 + 列表/地圖 toggle
- 日籤（D2/D3…）+ 輕量「列表/地圖」toggle，**跟內容捲、不釘死**。

### 2.3 當日票根抬頭
- 深墨、左右打孔洞；顯示「**地區 + 當天旅遊風格 + ✏️**」。
- 「**順路重排**」入口放這（從 ＋新增 移出；日層級操作）。

### 2.4 卡片
- **時間在前**（紅 mono）、地點襯線、**縮圖在左**（呼吸感）。
- 角色差異化保留（記帳拍立得微傾）——但**記帳是旅途，規劃臉不顯示**。

### 2.5 連接卡 = A（帶標籤瘦條）+ 編輯即自動接路
- A：`WALK / SUBWAY · N 分`（mono）。呼吸感 > 緊湊。**<5 分步行自動收合細線**（待辦）。
- **編輯即自動接路（核心）**：陣列＝順序、連接＝衍生的邊；**任何相鄰改變（加/拖/刪/插）只重算受影響的 2–3 條邊**，時間由 reconcile 骨牌下推。
- **geo-aware**：同城 walk/subway 自動估；跨城→城際交通卡（空間第三刀）或先跳「跑太遠」把關。
- 交通**自動填但可改**。**效率**：便宜估算做互動與運算、只在最後對確定的邊打貴 API（見 §5 效率分層）。

### 2.6 ＋新增 = v4 就地展開（inline in timeline）
- **不跳窗**：點空檔 → 建議就地在時間軸長出；上下文全在（看得到上一站、下一站的訂位牆）。
- **分層智慧選單（六點全含）**：
  1. 空檔智慧建議（Gap-fill）+ 情境感知（依空檔+學到偏好排序）
  2. 營業時間把關（Places 營業時間、軟提示不硬擋）
  3. 「加地點」同管線（心願盒/搜尋 都走「建議順路位置→自動接路→估時長」）
  4. 順路重排（已移到日抬頭）
  5. 交通降級為「自訂交通」（次要；交通已自動生成）
  6. 加入後：新站落下、上下兩邊自動接、後續時間骨牌、空檔縮小續推「先這樣 ✕」可收手
- 文案：**順路推薦 / 自行加入 / 換一組 / 順路重排**（非開發者口吻）。

### 2.7 自行加入（搜尋帶頭）+ Google Places
- 版式：搜尋帶頭 + **從心願盒（綠框突出）** + 匯入/自訂交通收邊。
- 搜尋引擎＝**Google Places（Autocomplete + Place Details）**（與現有地理編碼/封面照同源，一個 placeId 帶座標/營業/照片/評分）。
- 效率/安全：**session token** + debounce + **城市偏置（用 cityCentroids）** + `placeId→details` 快取 + **key 走後端 proxy** + 顯示「Powered by Google」。
- 選定→確認卡（照片/營業/評分 + 「建議放 14:00 · 順路 6 分」）→加入（走同一順路管線）。

### 2.8 從心願盒（就地）+ 心願全域
- 心願盒＝**全域**（靈感頁）；三時刻＝捕捉（app 外分享，iOS PWA 分享目標受限，落地時討論）/ 瀏覽（靈感頁，依城市分群）/ **就地**（規劃臉）。
- 規劃臉就地＝ ＋新增「從心願盒」（濾本趟城市）＋ 地圖圖釘。
- 加入語意（讀碼確認）：**地點＝複製**進 `stagedWishes`（原件留著）、**購物項＝參照**（設 `tripId`，跨趟＝搬移）。**建議加非破壞性軟已訪連結**（`usedInTrips`/`lastUsedAt`）——夢想不刪但知排過/去過、餵學習（§5 債）。

### 2.9 匯入分流 + 訂位投影 + 匯入即記帳
- **分流軸＝「有沒有固定地點＋時間、會掉進某天某時段」**：
  - 有（餐廳訂位、有時段票）→ **規劃臉**「新增訂位」。
  - 邊界/後勤/無時段（機票、飯店、通行證、無時段門票）→ **行前準備**（單一文件中樞）。
- **機票搬去行前準備匯入，但仍自動投影回規劃臉當錨**（搬介面、不搬錨定）。底層**一個 booking store、多視圖**；去重靠 pnr/bookingId 冪等（已有）。
- **訂位投影成行程（一個投影引擎、三種落點）**：機票→頭尾邊界卡（抵達=Day1 第一張=牆／離境=末日收尾）＋城際段；**飯店＝一段住宿（date range），每晚收尾卡、分階段**（入住/續住/退房前 11:00）；餐廳/有時段票→當天某時段。
- **匯入即記帳**：匯入訂位時同步落一筆帳（金額＋付款人＋可分帳）到同一本 ledger。
- 圖二（規劃臉匯入 sheet）重畫：標題「新增訂位」、副標「餐廳・有時段票・排進這天」、底部導向「機票/飯店 → 行前準備統一匯入」＋去重保證文案。

### 2.10 地圖圖釘 = v2（地圖 + 底部清單連動）+ 六點
- 心願＝綠星、行程站點＝墨編號 + 虛線動線；圖例區分。
- **可見度切換：全部顯示 / 篩選 / 屏蔽** + 類別 chip（防雜亂）。點釘/點卡連動→底卡→加入。
- 六點：①加入要說去哪（接 `suggestDayNumber`）②地圖範圍+順路基準明確（日選擇器）③清單排序有邏輯可見 ④沿路探索（動線緩衝帶）⑤地圖上直接插入（拖釘/選插入點、不得插在抵達錨前）⑥整趟多日分色動線（接 geoCheck、限制天數）。

### 2.11 拖曳微調 = v1（卡片式）+ 牆
- 即時回饋 pill（落點+結果時間+順移+≈估算「放開精算」）；ghost 原位；綠色插入指示線。
- 牆抵抗（機票/訂位/飯店不被擠走）；**你的擺放優先於生成**（拖過→`priority=user`，順路重排/gap-fill 不得偷排回）。
- 預設：跨天＝「移到其他天」選單；撞牆放不下＝就近吸附有效位、真塞不下丟 ParkedTray。
- （v2 時間尺**未採為主檢視**；僅借用其「鎖定斜紋」概念。）

### 2.12 卡片鎖定（統一「牆」）
- 訂位/機票/飯店＝**事實自動鎖（紅斜紋）**；使用者可**手動鎖任意卡（墨斜紋＋鎖頭）**；共用 reconcile 牆邏輯 + `movable`/`priority`。
- 互動：長按卡→「🔒鎖定時間/編輯/移到其他天/刪除」。
- 警示：①鎖了來不及（遲到，沿用 ParkedTray/衝突）②兩鎖物理矛盾（必偵測提示）③兩站都鎖中間交通照樣自動接。
- **開放（落地時討論）**：紅=訂位事實鎖如何精準判斷；使用者解鎖互動。

## 3. 落地順序（Phase A–F）

- **A · 簽名視覺套用**（風險低、最可見）：封面、日抬頭、卡片（時間前/縮圖/襯線）、連接卡 A、移除工具列。純 restyle，吃現有 ItineraryView。
- **B · 資料地基（支撐後面）**：Activity discriminated union + type 嚴格聯合；連接卡投影化收尾；`movable`/`priority`（已有）接鎖定；心願軟已訪連結。
- **C · 編輯即自動接路 + 效率層**：routing（haversine 估算 + 運具啟發式 + 距離矩陣快取 + debounced Directions）；接進 reconcile/scheduler。
- **D · ＋新增 v4 就地 + 自行加入 + Places 搜尋 + 從心願盒**；順路重排（日抬頭）。
- **E · 拖曳微調 + 卡片鎖定**（牆/衝突/矛盾警示）。
- **F · 地圖圖釘 v2**（六點）。
- **F' · 匯入分流 + 訂位投影（飯店/餐廳）+ 匯入即記帳**——**需先設計行前準備**（見 §6）。

驗收：每 Phase 收尾 `tsc --noEmit` 綠 + 相關單元測試綠 + 截圖比對簽名。

## 5. 資料結構債（地基第二輪 + 本輪新增）

- **記帳獨立成 transaction/ledger 實體**（真會計/分帳/跨幣別/結算；規劃臉拍立得＝該筆的視圖，不副本）。
- **Activity 判別聯合化**；`type` 收嚴格聯合、非 `|string`。
- **圖片欄位收斂**（image vs expenseImage/Path）；**`layout` 不存**（由 type 衍生）；**連接卡投影化**；系統卡 vs 真站分清。
- **心願軟已訪連結**（`usedInTrips`/`lastUsedAt`）；地點「複製 vs 參照」不對稱收斂。
- **訂位投影引擎**：機票 anchor（`projectAnchors` 已有）＋飯店 stay 投影（新）＋訂位 slot 投影。
- **Booking → ledger entry**（匯入即記帳）。

## 7. 全域文案原則
- 像雜誌編輯/禮賓，不像系統或工程師；不賣萌、不報系統訊息；mono 事實式數據＝專業感來源。
- 內部「臉」不進 UI；用真實頁籤名。
- 安心陳述、時間開頭、無「AI/生成」字眼（沿用既有原則）。
