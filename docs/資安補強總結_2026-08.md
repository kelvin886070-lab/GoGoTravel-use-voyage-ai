# 白話版

## 一句話
把「使用者的資料是否安全」從**靠我小心**，改成**靠結構擋住**——就算我哪天忘記、或有人惡意攻擊，系統本身會擋下來。

## 我們擔心的兩種風險，分開處理
- **對使用者的風險**（資料外洩）：最優先，因為不可逆。查證結論——**沒有發生**。使用者的護照/證件存放區從頭到尾只有本人能讀，且目前只有一位使用者（你自己），沒有任何外洩。
- **對我們的風險**（帳單被刷爆、服務被濫用）：可逆，但要防。這次補的大多屬這類。

## 修好的幾件大事（白話）
1. **費用有了大門警衛**：以前最貴的兩個 AI 功能沒人看管，等於免費無限用。現在所有功能都要先到大門「扣點數」，每人每天有額度，貴的功能扣得多，用完自動恢復。沒登記在名單上的功能，一律不放行。
2. **別人不能偷點更貴的服務**：以前有心人可以繞過我們的 app、直接要求「用最貴的 AI、輸出拉到最大」。現在這些都由我們的伺服器決定，外面塞什麼都沒用（已實測確認）。
3. **伺服器不再幫陌生人跑腿**：修好一個「可以叫我們伺服器去連任何網址」的漏洞。現在它只認 Google 地圖，別的一律拒絕（已實測確認）。
4. **頭像區的門鎖補上**：發現任何登入者都能覆蓋別人的頭像、或把垃圾檔塞進來燒我們流量——已修成「只能碰自己的」。
5. **一個會被惡意 PDF 攻擊的漏洞**：上傳一份動過手腳的 PDF 有可能劫持帳號——已升級修補。
6. **一把不小心留在紀錄裡的舊鑰匙**：已作廢，留著也打不開任何門。

## 現在能誠實回答的一題
「我的護照存在你這裡，經過哪些地方？」→ **只在你的私人存放區（private bucket，RLS 只有你讀得到），不經過任何第三方 AI。**
要在畫面上顯示時，系統為你產生一條**短時效臨時連結**（證件 1 小時 / 批次預載 24 小時），該連結只存在你這台裝置的當下畫面、重整即消失、不寫入資料庫、不隨分享行程外傳。
（唯一會送 AI 的，是你主動選擇「匯入訂房」時那一份檔案——該檔含個資，上架前會白紙黑字寫進隱私政策。保管箱檔案不送 AI。）

### signed URL 資料流（覆核 D-2 查證結果，2026-08-15）
| 問題 | 查證結果 | 檔案證據 |
|---|---|---|
| 有效期多長 | vault 證件：隨開隨簽 **1h**、批次預載 **24h**；trip-media 旅遊照才 7 天 | `VaultView.tsx:197`(1h)、`App.tsx:390`(24h)、`storage.ts:14`(7d 僅 trip-media) |
| 會被持久化嗎 | vault 的 URL **只進 React 記憶體**（重整即消失），**不寫 localStorage、不寫 DB**。7 天 localStorage 快取（`kt_signed_urls_v1`）**程式碼註解明確只收 trip-media，排除 vault** | `storage.ts:8-14` 註解「vault（證件）不走此快取」 |
| 會流入分享嗎 | **不會**。DB 只存**路徑**不存 URL；分享走 DB／trip_data，序列化的是路徑不是 signed URL | `storage.ts:2`「資料庫只存路徑」 |
| 登出 | 快取整份清空（換帳號不撿到上一位的鑰匙） | `clearSignedUrlCache()` |

結論：vault 設計**穩健**。「只有你能開」精修為「**只有你能產生開啟連結，連結短時效且不外傳**」——底層不是宣稱，是可驗證的事實。
